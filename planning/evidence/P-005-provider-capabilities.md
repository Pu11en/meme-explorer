# P-005 — Provider capabilities for real-time Solana/Pump.fun candidate signals

- Accessed: 2026-08-25
- Scope: discovery, market-activity, liquidity, token-state, and risk-enrichment data that could become **inputs** to a buy-candidate system. This note deliberately does not choose trading thresholds.
- Evidence rule: first-party documentation, published API schemas, or owner-controlled source repositories only. Unofficial wrappers, reverse-engineered frontend endpoints, scraper blogs, and undocumented `pump.fun` web routes are excluded.

## Timing vocabulary

The providers do not publish directly comparable end-to-end latency guarantees for these interfaces. Timing below therefore uses categories, not invented millisecond claims:

- **Chain push — processed/confirmed/finalized:** subscription triggered by validator observation at the selected Solana commitment.
- **Provider push — near-real-time:** provider-derived event delivered over WebSocket/SSE; transformation and indexing delay is unspecified.
- **Polled current snapshot:** current/rolling provider view fetched by HTTP; freshness depends on provider indexing and caller polling.
- **Analytical/cache enrichment:** generated or cached derived report; not appropriate as the sole first-discovery clock.

## Source-by-source notes and exact citations

### 1. PumpPortal

Primary docs: [real-time Pump.fun/PumpSwap data](https://pumpportal.fun/data-api/real-time), [fees](https://pumpportal.fun/fees/), and [FAQ/rate-limit guidance](https://pumpportal.fun/FAQ/).

- Best fit: very early managed discovery (`subscribeNewToken`), migration detection, and mint/account trade flow without implementing program decoding first.
- The page documents subscriptions but not an output JSON schema. Treat all returned event properties as provider payload observations, schema-version them internally, and retain unknown fields.
- Do not open one socket per mint. Send additional subscriptions over one connection and unsubscribe with the documented methods.

### 2. Native Solana RPC / WebSocket

Primary docs: [clusters/public endpoint limits](https://solana.com/docs/references/clusters), [commitment](https://solana.com/docs/rpc#configuring-state-commitment), [`logsSubscribe`](https://solana.com/docs/rpc/websocket/logssubscribe), [`programSubscribe`](https://solana.com/docs/rpc/websocket/programsubscribe), unstable [`blockSubscribe`](https://solana.com/docs/rpc/websocket/blocksubscribe), [`getTransaction`](https://solana.com/docs/rpc/http/gettransaction), [`getProgramAccounts`](https://solana.com/docs/rpc/http/getprogramaccounts), and [`getTokenLargestAccounts`](https://solana.com/docs/rpc/http/gettokenlargestaccounts).

- For Pump activity, subscribe to the official program address in `logsSubscribe.mentions`, then fetch/decode the transaction, or consume full matching blocks/transactions where supported.
- `programSubscribe` is account-state change notification, not instruction/event notification. It is useful for bonding curve/pool state only when account layouts and filters are known.
- Record slot, signature, commitment, local receipt time, and decoded event timestamp separately; they describe different clocks.

### 3. Helius

Primary docs: [`transactionSubscribe` guide](https://www.helius.dev/docs/rpc/websocket/transaction-subscribe), [API reference](https://www.helius.dev/docs/api-reference/rpc/websocket/transactionsubscribe), [LaserStream gRPC](https://www.helius.dev/docs/laserstream/grpc), [plans](https://www.helius.dev/docs/billing/plans), and [credits](https://www.helius.dev/docs/billing/credits).

- The official guide contains a Pump.fun example filtering `accountInclude` on the Pump program and then inspecting transaction logs/accounts.
- Helius reduces RPC plumbing and permits richer transaction filters, but it does not eliminate the need for the official Pump/PumpSwap IDLs when correctness matters.

### 4. Birdeye

Primary docs: [WebSocket overview/access](https://docs.birdeye.so/docs/websocket), [`SUBSCRIBE_TOKEN_NEW_LISTING`](https://docs.birdeye.so/reference/new-token-listing), [`SUBSCRIBE_NEW_PAIR`](https://docs.birdeye.so/reference/new-pair), [`SUBSCRIBE_MEME`](https://docs.birdeye.so/reference/meme-stats), [`SUBSCRIBE_TXS`](https://docs.birdeye.so/reference/tokenpair-transactions), [`SUBSCRIBE_PRICE`](https://docs.birdeye.so/reference/subscribe_price-ohlcv), [`SUBSCRIBE_TOKEN_STATS`](https://docs.birdeye.so/reference/token-stats), [HTTP new listings](https://docs.birdeye.so/reference/get-defi-v2-tokens-new_listing), [token security](https://docs.birdeye.so/reference/get-defi-token_security), [package accessibility](https://docs.birdeye.so/docs/data-accessibility-by-packages), [compute cost](https://docs.birdeye.so/docs/compute-unit-cost), and [pricing](https://docs.birdeye.so/docs/pricing).

- `SUBSCRIBE_MEME` can filter `source:"pump_dot_fun"` and emits identity/metadata; price, liquidity, supply, FDV, holder count/top-10 percentage; interval buy/sell/volume fields; creation/graduation transaction, slot, time, creator and progress; pool reserves; and sniper/bundler/insider/dev count and held-percentage fields. A new same-type subscription overwrites all prior filters.
- `SUBSCRIBE_TXS` accepts token or pair addresses and `txsType` (`all`, `swap`, `add_remove_liquidity`, `add_liquidity`, `remove_liquidity`). `TXS_DATA` exposes transaction time, owner, source, hash, side, token/pool/platform, USD volume and price plus from/to amount/decimal/price fields. It supports at most 100 addresses, and simple/complex query response shapes differ.
- `SUBSCRIBE_PRICE` emits `PRICE_DATA` OHLCV, including Solana `1s`, `15s`, and `30s` intervals, but Birdeye documents an internal ranking-pool mechanism: not every transaction causes a price update. Use `SUBSCRIBE_TXS` for event-level flow.
- REST `/defi/token_security` and `/defi/token_overview` provide authority, concentration, holder, supply, liquidity and rolling market enrichment as pull snapshots.
- Entitlement documentation conflicts: the WebSocket guide says Business-only with 500 default connections, while the current Pricing page says Premium includes WebSockets/500 and Business includes 2,000. Confirm the account entitlement rather than hard-coding either statement. WS output is CUPB-metered and documented costs can change.
- Keep `source`, `txHash`, `blockTime`, and the provider receipt time so events can be reconciled with chain data.

### 5. DEX Screener

Primary docs: [API reference](https://docs.dexscreener.com/api/reference), [official WebSocket API](https://docs.dexscreener.com/api/websockets.md), [token-listing rule](https://docs.dexscreener.com/token-listing), and [API terms](https://docs.dexscreener.com/api/api-terms-and-conditions).

- Useful after a pair has begun trading: cross-DEX price/liquidity, rolling transactions/volume, pair age, metadata, and paid-attention context.
- The official WebSockets push profile updates, community takeovers, ads and boosts only. They do not expose Pair price/trade/volume/liquidity/market-cap fields or a comprehensive new-token/new-pair stream.
- Not suitable as the only creation detector because the official listing rule requires a pool plus at least one transaction; Pair market data remains polling-only.

### 6. RugCheck

Primary source: RugCheck-owned [Swagger JSON](https://api.rugcheck.xyz/swagger/doc.json) (the authoritative machine-readable endpoint list/schema).

- Use summary fields as explainable enrichment: persist the individual `risks[]`, authorities, lock percentage, token program/type, report time/cache mode, and raw response—not only an aggregate score.
- The lack of a Swagger response schema for the full report means consumers should not hard-code undocumented full-report fields without contract tests.

### 7. Jupiter

Primary docs: [Tokens V2 guide](https://dev.jup.ag/docs/tokens/v2), [Tokens recent](https://developers.jup.ag/docs/api-reference/tokens/recent), [Tokens category](https://developers.jup.ag/docs/api-reference/tokens/category), [Price V3 guide/reference](https://developers.jup.ag/docs/price), current [Swap V2 order](https://developers.jup.ag/docs/api-reference/swap/order), [plans](https://developers.jup.ag/docs/portal/plans), and [rate limits](https://developers.jup.ag/docs/portal/rate-limits).

- Useful for indexed token facts, authority flags, holder/liquidity/market stats, suspicious/organic heuristics, a recency-by-first-pool list, USD price with `blockId`, and route-aware quote checks.
- Swap V2 order returns route/amount/USD values, `priceImpact`, fees, route/router, and—with a taker—a built transaction and expiry context. It is request-time and amount-dependent, not an execution guarantee. Legacy Swap V1 is documented as superseded/not actively maintained.
- Preserve the distinction between “no returned price,” “no route for this amount,” “flagged suspicious,” and “not yet indexed.” They are not equivalent outcomes.

### 8. Official Pump.fun program documentation

Primary owner-controlled sources: [`pump-fun/pump-public-docs`](https://github.com/pump-fun/pump-public-docs), [Pump program README](https://github.com/pump-fun/pump-public-docs/blob/main/docs/PUMP_PROGRAM_README.md), [Pump IDL](https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump.json), and [PumpSwap IDL](https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump_amm.json).

- Legitimate official capability is the on-chain program contract/IDL, not a documented Pump.fun-hosted data service.
- The evidence search found no owner-documented REST or WebSocket endpoint for the Pump.fun website’s discovery feed. Reverse-engineered website APIs are therefore out of scope and must not be presented as official.

## Practical role separation (not a provider ranking)

These sources expose different clocks and should not be treated as interchangeable:

1. **First observation:** PumpPortal provider push, or native/Helius chain push decoded with official Pump IDLs.
2. **Chain reconciliation:** signature, slot, success/failure, balances, reserves, and commitment from Solana/Helius.
3. **Rapid managed enrichment:** Birdeye new-pair/listing/stats and Jupiter token/price/quote views.
4. **Post-listing market context:** DEX Screener pair/liquidity/rolling activity.
5. **Risk enrichment:** explicit RugCheck risk records plus on-chain authority/holder/lock facts; never a provider score alone.

A production evaluator should store source, source event time/block time, local receipt time, slot/commitment, and raw payload/version for every fact. None of the reviewed providers documents enough latency/completeness/SLA information to infer a universal fastest or most complete source without a controlled measurement phase.
