# Infrastructure repository audit — corrected claims

**Audited:** 2026-08-26 07:57 UTC  
**Scope:** `rpcpool/yellowstone-grpc`, `solana-labs/solana-accountsdb-plugin-postgres`, `nathanliow/pumpscope`, `vicentszr/pump-tracker`, and `rckprtr/pumpdotfun-sdk`.  
**Method:** GitHub repository/API metadata, default-branch source at the commit IDs below, repository-owned CI configuration, and owner documentation for required services. Counts are point-in-time observations. A public repository, a successful HTTP response, or a nominal free tier is availability evidence—not an SLA, a completeness promise, or a future entitlement.

## Executive correction

None of the five repositories is a turnkey, managed, SLA-backed, genuinely FREE-ONLY Pump.fun data-and-replay service.

- **Yellowstone gRPC** is the strongest actively maintained infrastructure codebase here, but it is a validator-side streaming plugin, not a free endpoint or durable archive. Its built-in replay is a bounded recent-slot buffer (150 slots by default). Self-hosting requires validator-grade infrastructure; Triton-hosted access is metered.
- **The Solana Labs PostgreSQL plugin** really can persist selected accounts, slots, transactions, block metadata, and optional account-change history, but the inspected branch is an old Solana 1.17.3 reference implementation. It is not a Pump.fun parser or replay service, and current development has moved to Anza's fork.
- **PumpScope** is explicitly an exploration, not production software. Its mainnet live path requires paid Helius LaserStream access, and its only local storage is process memory.
- **PumpTracker** is a two-file browser demo, not a real-time collector. Its market/chart lane depends on public indexed APIs; its “whale” lane exposes a Helius credential in client source. It claims MIT while shipping no `LICENSE` file.
- **pumpdotfun-sdk** is a third-party transaction SDK, not an official Pump.fun repository, recorder, or replay system. Read-only calls can use an RPC, but create/buy/sell require a funded signer and on-chain fees. Its tests only smoke-test package exports/browser loading, not protocol behavior.

## Repository-by-repository findings

### 1. `rpcpool/yellowstone-grpc`

**Correct capability claim.** This is Triton One's actively maintained Solana Geyser gRPC implementation. The owner README says it streams slots, blocks, transactions, account updates, and deshred pre-execution transactions, with Go/Rust/TypeScript/Python examples ([README](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/README.md#L1-L7)). The protobuf exposes bidirectional subscriptions, account/slot/transaction/block/entry filters, commitments, `from_slot`, replay-info, and several unary methods ([proto](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/yellowstone-grpc-proto/proto/geyser.proto#L10-L50)).

**Important deshred correction.** The API surface does not mean the default open-source server implements every advertised stream. The owner README expressly says `SubscribeDeshred` is available only on Triton extension servers; `master` returns `UNIMPLEMENTED`, while the implementation lives on `master-triton-ext` ([README](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/README.md#L369-L385)).

**Storage/replay.** `from_slot` is real, and recent replay supports reconnect/backfill. It is not durable historical storage: configuration describes `replay_stored_slots` as the number of slots held for rebroadcast and defaults it to **150** ([config](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/yellowstone-grpc-geyser/src/config.rs#L356-L361), [default](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/yellowstone-grpc-geyser/src/config.rs#L633-L635)). Durable retention requires adding another system; the README separately links a Kafka bridge project ([README](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/README.md#L482-L484)).

**Tests/CI.** This is the most substantial test posture in the set. The repository contains extensive Rust unit/async tests and GitHub workflows for Rust, Node/N-API and TypeScript integration. The principal workflow runs formatting, Clippy, feature checks, `cargo test --all-features`, and a build test on pushes/PRs ([workflow](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/.github/workflows/test.yml#L7-L18), [test steps](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/.github/workflows/test.yml#L101-L122)). Workflow presence is not a guarantee that every release or deployment is healthy; inspect [current Actions runs](https://github.com/rpcpool/yellowstone-grpc/actions) when pinning a revision.

**License.** The default project license is **AGPL-3.0-only**. `examples`, `yellowstone-grpc-client`, `yellowstone-grpc-client-nodejs`, and `yellowstone-grpc-proto` are separately Apache-2.0 ([licensing map](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/LICENSING.md#L1-L16)). A blanket “Apache-2.0 Yellowstone” claim is false.

**Credentials/services and FREE-ONLY verdict.** Self-hosting needs a compatible Solana/Agave validator with the Geyser plugin, networking, compute, and operations. Auth can be omitted or self-configured; the code supports TLS and file/HTTP/trusted-metadata auth ([README auth](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/README.md#L25-L33), [auth modes](https://github.com/rpcpool/yellowstone-grpc/blob/37a5d0e3dd85b5b41c59e30dab86f25a449b7fba/README.md#L99-L120)). That makes the source usable without a paid API credential if the operator already owns the infrastructure; it does **not** create a free managed data lane. Triton's hosted Yellowstone access is usage-priced and token-authenticated ([owner pricing](https://www.triton.one/pricing/), [Dragon's Mouth docs](https://docs.triton.one/project-yellowstone/dragons-mouth-grpc-subscriptions)). **Strict FREE-ONLY managed eligibility: no. Conditional self-host source eligibility: yes, but not zero-cost.**

### 2. `solana-labs/solana-accountsdb-plugin-postgres`

**Correct capability claim.** This is a validator Geyser reference plugin that writes selected account state to PostgreSQL, optionally selects transactions, and stores slots and block metadata. Account selection supports pubkeys, program owners, or `*`; transactions are not stored unless `transaction_selector` is configured ([README account filters](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/README.md#L55-L82), [transaction selection](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/README.md#L84-L113)). The schema includes `account`, `slot`, `transaction`, `block`, token-owner/mint indexes, and `account_audit` ([schema](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/scripts/create_schema.sql#L7-L30), [transactions/blocks](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/scripts/create_schema.sql#L162-L207)). It does not decode Pump.fun instructions or produce token-level analytics.

**Storage/replay.** Persistence is genuine, but “full historical replay” is too broad. The normal `account` table is latest-state upsert storage. Account-change history is opt-in through `store_account_historical_data` plus an audit trigger, and operators must manage its unbounded growth ([README](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/README.md#L211-L252)). The plugin records only what the attached validator emits after installation/selection; it has no documented network backfill, event replay API, retention SLA, or Pump.fun-specific redecoder.

**Currency/ownership correction.** The inspected crate is pinned to Solana **1.17.3** in its manifest ([Cargo.toml](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/Cargo.toml#L1-L33)), and the default-branch head is from 2023. Current development is in the owner-successor [`anza-xyz/agave-geyser-plugin-postgres`](https://github.com/anza-xyz/agave-geyser-plugin-postgres), identified by GitHub as a fork of the Solana Labs repository. Treating the Solana Labs branch as the current Agave production plugin is outdated.

**Tests/CI.** The repo has Rust unit tests and PostgreSQL integration tests. Its GitHub workflow starts PostgreSQL, checks format and Clippy, then runs a script that builds and executes `cargo test` ([workflow](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/.github/workflows/test.yml#L1-L60), [build/test script](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/ci/cargo-build-test.sh#L11-L15)). The workflow uses old `actions/checkout@v2`, `actions/cache@v2`, and `actions-rs`; configuration existence does not prove it still passes on current GitHub runners.

**License.** GitHub detects no repository license and no `LICENSE` file exists at the inspected head, but `Cargo.toml` declares `license = "Apache-2.0"` ([manifest](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/Cargo.toml#L1-L9)). Correct wording is **“crate manifest declares Apache-2.0; repository omits the license text and GitHub does not detect a license,”** not simply “unlicensed” and not “ships a complete Apache-2.0 license.” Resolve licensing provenance before redistributing source.

**Credentials/services and FREE-ONLY verdict.** No proprietary API key is required, but an operator needs a compatible validator, PostgreSQL credentials/certificates, substantial compute/storage, schema setup, and ongoing database administration. The README recommends separate validator/database hosts and cites very large GCP machine examples for all-account capture ([configuration](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/README.md#L5-L45), [performance](https://github.com/solana-labs/solana-accountsdb-plugin-postgres/blob/37d0105ba91e304324c37e8fcaf71a827fb2bfd2/README.md#L268-L279)). **Managed FREE-ONLY eligibility: no. Self-host software without paid credentials: conditionally yes, but the infrastructure is not free and the branch is obsolete.**

### 3. `nathanliow/pumpscope`

**Correct capability claim.** PumpScope is a Next.js/React dashboard and server that subscribes to Pump.fun transactions through Helius LaserStream, parses create/buy/sell/migrate-like activity, fetches Helius DAS metadata/history/funding data, serves live token/trade updates, charts activity, and includes client-side paper trading. The owner explicitly labels it a Helius MCP exploration “not intended for production use” ([README](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/README.md#L1-L20)).

**Storage/replay.** The live token store is an in-process `Map`; it prunes token entries and 24-hour trade arrays and disappears on restart ([store](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/src/server/store.ts#L1-L37), [pruning](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/src/server/store.ts#L84-L96)). Its `/api/history` route fetches Helius enhanced transaction history on demand; that is provider-backed lookup, not local persistence or deterministic replay ([route](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/src/app/api/history/%5Bmint%5D/route.ts#L1-L20), [Helius client](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/src/lib/helius.ts#L42-L53)). No durable database, raw event log, reconnect ledger, or replay tool is present.

**Tests/CI/license.** The repository contains no test files, no test script in `package.json`, and no `.github/workflows` directory ([package.json](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/package.json#L1-L29)). It also has no license file or manifest license. Public visibility permits reading/forking on GitHub; it does not grant a general copyright license to reuse the code.

**README/runtime mismatch.** The README shows `PORT=3001`, says the app runs at 3000 and describes a separate WebSocket server on 3001 ([README](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/README.md#L37-L57)). The checked-in `.env.example` instead uses port 3000, and `server.ts` attaches `/ws` to the same HTTP server/listening port ([environment](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/.env.example), [server](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/server.ts)). The documented two-port setup is outdated.

**Credentials/services and FREE-ONLY verdict.** `HELIUS_API_KEY` is mandatory for the Helius RPC/DAS/enhanced transaction/funded-by calls, and the project's own environment example says the **Professional plan is required for mainnet LaserStream** ([env example](https://github.com/nathanliow/pumpscope/blob/b9f35e6053dbaafbf41cb6be5e8f4a7da92809f0/.env.example#L1-L5)). Current Helius owner docs say mainnet LaserStream requires Business or Professional ([LaserStream docs](https://www.helius.dev/docs/laserstream), [plans](https://www.helius.dev/docs/billing/plans)). CoinGecko is also called for SOL/USD. **Genuine FREE-ONLY mainnet eligibility: no.** Falling back to Helius polling still requires the key and metered Helius services; it does not create a no-credential lane.

### 4. `vicentszr/pump-tracker`

**Correct capability claim.** This is a static `index.html` browser dashboard. On user search it fetches a DEX Screener token snapshot, requests GeckoTerminal OHLCV, and samples Helius transactions to derive a “whale” table ([data flow in README](https://github.com/vicentszr/pump-tracker/blob/8ad7dcf8107b1ab3cf3b29cf9899d5e86c7ead31/README.md#L55-L77), [DEX/refresh code](https://github.com/vicentszr/pump-tracker/blob/8ad7dcf8107b1ab3cf3b29cf9899d5e86c7ead31/index.html#L492-L576)). There is no WebSocket, server, background collector, or timer that refreshes market data. Calling it a “real-time scanner” or live creation feed is inaccurate; it is an on-demand indexed-data viewer.

**Whale/24-hour correction.** The code takes at most 100 recent signatures, truncates to 50 for Helius parsing, groups by fee payer, infers buy/sell from token-transfer direction, and labels the result “Top Traders (24h)” without applying a 24-hour timestamp filter ([implementation](https://github.com/vicentszr/pump-tracker/blob/8ad7dcf8107b1ab3cf3b29cf9899d5e86c7ead31/index.html#L378-L464)). It therefore does not establish complete top-10 traders, true actor identity, exact trade direction, or a complete 24-hour window.

**Storage/replay/tests/CI.** The repository contains only `README.md` and `index.html`. There is no persistence, replay/backfill tool, test suite, build, lockfile, or CI workflow. OHLCV is historical provider data, not repository-owned replay.

**License correction.** The README badge and text claim MIT and link to `LICENSE`, but the repository has no `LICENSE` file ([README claim](https://github.com/vicentszr/pump-tracker/blob/8ad7dcf8107b1ab3cf3b29cf9899d5e86c7ead31/README.md#L1-L7), [license statement](https://github.com/vicentszr/pump-tracker/blob/8ad7dcf8107b1ab3cf3b29cf9899d5e86c7ead31/README.md#L110-L112)). GitHub accordingly detects no license. Do not treat the broken badge as a complete MIT grant without owner clarification/a committed license text.

**Credential/security and FREE-ONLY verdict.** The JavaScript commits a Helius API key directly into public browser source and sends it to Helius RPC and enhanced-transaction endpoints ([source—credential intentionally not reproduced](https://github.com/vicentszr/pump-tracker/blob/8ad7dcf8107b1ab3cf3b29cf9899d5e86c7ead31/index.html#L231-L233), [uses](https://github.com/vicentszr/pump-tracker/blob/8ad7dcf8107b1ab3cf3b29cf9899d5e86c7ead31/index.html#L378-L411)). A leaked/embedded owner key is not a legitimate free entitlement for downstream users and may be revoked or exhausted. The no-key DEX Screener/GeckoTerminal portion is a best-effort free public lane subject to those owners' limits; the Helius whale feature fails strict FREE-ONLY rules. **Whole-app genuine FREE-ONLY eligibility: no. Market/chart-only subset: conditionally yes, best effort.**

**Observed availability versus SLA.** The README demo `https://pump-tracker.vercel.app/` and the repository-homepage deployment `https://pump-tracker-six.vercel.app/` both returned HTTP 200 in low-volume requests at 2026-08-26 08:08 UTC. The URL divergence is itself a documentation/metadata inconsistency. These probes prove only that both root HTML pages were reachable then; they do not prove the three dependent APIs or every feature worked. The repository provides no uptime, support, retention, correctness, or continuity SLA; Vercel's published SLA applies to Enterprise, not a hobby deployment ([Vercel SLA](https://vercel.com/legal/sla), [Hobby plan](https://vercel.com/docs/plans/hobby)).

### 5. `rckprtr/pumpdotfun-sdk`

**Correct capability claim.** This is a community/third-party TypeScript SDK owned by `rckprtr`, not the official `pump-fun` organization. It builds Pump.fun bonding-curve create, buy, and sell transactions; reads global/bonding-curve accounts; calculates prices/slippage; uploads token metadata; and subscribes to Anchor events ([README overview](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/README.md#L7-L25), [implementation](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/src/pumpfun.ts#L54-L171), [events](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/src/pumpfun.ts#L446-L501)). It hard-codes the legacy Pump.fun program/IDL and calls `https://pump.fun/api/ipfs` for metadata ([program](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/src/pumpfun.ts#L42-L52), [upload](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/src/pumpfun.ts#L395-L444)). It does not implement PumpSwap, market scanning, analytics, or provider-independent historical decoding.

**Currency correction.** The default branch has not moved since 2025-04-11 and has many open issues/PRs. More decisively, the checked-in IDL no longer matches Pump's current owner IDL: this SDK's legacy `buy` has 2 arguments/12 accounts and `sell` has 2 arguments/12 accounts, while the current official IDL has 3 arguments/16 accounts for legacy `buy` and 2 arguments/14 accounts for legacy `sell`; the official IDL also includes `buy_v2`/`sell_v2`, which this SDK lacks ([SDK IDL](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/src/IDL/pump-fun.json), [current official IDL](https://github.com/pump-fun/pump-public-docs/blob/9c82f61cb711b044a17f770ab8ce9f9bdf78f333/idl/pump.json)). Pump's owner docs urge integrations to move to the unified v2 trade instructions and identify the owner SDKs ([official README](https://github.com/pump-fun/pump-public-docs/blob/9c82f61cb711b044a17f770ab8ce9f9bdf78f333/README.md#L17-L35), [SDK links](https://github.com/pump-fun/pump-public-docs/blob/9c82f61cb711b044a17f770ab8ce9f9bdf78f333/README.md#L84-L93)). Consequently, the README's current create-and-buy/buy/sell walkthrough is outdated: `create` still matches by simple account/argument count, but any path containing this SDK's buy/sell must be treated as incompatible or at minimum unverified against the current program. Do not call it a current or official SDK. Pump.fun now publishes the separate official package [`@pump-fun/pump-sdk`](https://www.npmjs.com/package/@pump-fun/pump-sdk).

**GitHub/npm artifact discrepancy.** `main/package.json` declares version 1.5.2 under MIT, but the registry's `latest` artifact was still 1.4.2 and reported ISC metadata at audit time ([GitHub package](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/package.json), [npm registry metadata](https://registry.npmjs.org/pumpdotfun-sdk/latest)). Therefore `npm i pumpdotfun-sdk` does not install the audited GitHub `main` artifact, and its version/license metadata should not be conflated with the repository.

**Storage/replay.** There is no database, event log, checkpoint, replay, backfill, or historical query layer. `addEventListener` is a live RPC/Anchor subscription only. Applications must supply persistence and gap recovery.

**Tests/CI.** `package.json` defines `test:builds`, which builds and runs three package-load smoke tests ([package](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/package.json#L19-L27)). The ESM/CJS tests only assert that `PumpFunSDK` can be imported and is a function ([ESM test](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/__tests__/esm.test.mjs), [CJS test](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/__tests__/cjs.test.cjs)); the browser test checks bundle page loading with web security disabled ([browser test](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/__tests__/browser.test.mjs#L1-L42)). There are no transaction-construction assertions, mocked account fixtures, local-validator tests, mainnet integration tests, or `.github/workflows` CI. “Tested SDK” must be narrowed to **packaging smoke-tested**.

**License.** MIT is consistently present in both the committed [`LICENSE`](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/LICENSE) and package manifest ([package.json](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/package.json#L31-L42)).

**Credentials/services and FREE-ONLY verdict.** The SDK itself does not require Helius specifically, although the examples require `HELIUS_RPC_URL`; callers can provide another compatible Solana connection ([example](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/README.md#L19-L52)). Read-only account/event operations may fit a best-effort public RPC lane. However, create/buy/sell require private signing keys, a funded wallet, rent/transaction/priority fees, and trade capital; the README asks for at least 0.004 SOL ([README](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/README.md#L19-L25)). **Advertised write-path FREE-ONLY eligibility: no. Read-only subset: conditionally yes, with no SLA and no replay.**

## False, misleading, or outdated statements to remove

1. **“Yellowstone gRPC is a free endpoint/service.”** False. It is open-source server/client code; hosted Triton access is a separate metered service, while self-hosting requires a validator and operations.
2. **“Yellowstone provides historical/archive replay.”** Misleading. The built-in replay is a bounded recent-slot rebroadcast buffer, default 150 slots—not durable archive retention.
3. **“Open-source Yellowstone master supports deshred streaming.”** False. The protobuf/client surface exists, but the server on `master` returns `UNIMPLEMENTED`; Triton extension servers/branch implement it.
4. **“Yellowstone is entirely Apache-2.0.”** False. The default is AGPL-3.0-only; only named client/proto/example directories are Apache-2.0.
5. **“The Solana Labs PostgreSQL plugin is the current production Agave plugin.”** Outdated. The inspected branch is pinned to Solana 1.17.3; current development is under `anza-xyz/agave-geyser-plugin-postgres`.
6. **“The PostgreSQL plugin stores all transactions/history by default.”** False. Transactions require an explicit selector; account audit history is opt-in; capture starts with the attached validator and there is no replay API/backfill promise.
7. **“The PostgreSQL repository is simply unlicensed” / “ships Apache-2.0.”** Both are incomplete. Its crate manifest declares Apache-2.0, but no license text is committed and GitHub detects none.
8. **“PumpScope is a free production Pump.fun stream/replay stack.”** False. Its owner says it is non-production, mainnet LaserStream requires a paid Helius plan, storage is in-memory, and history is fetched on demand from Helius.
9. **“PumpScope has tests/CI.”** False at the inspected commit: no tests, test script, or GitHub workflow exists.
10. **“PumpScope runs the app at 3000 and a separate WebSocket server at 3001.”** Outdated. Current code serves `/ws` from the same HTTP server/port, and `.env.example` uses 3000.
11. **“PumpTracker is an MIT-licensed real-time scanner.”** Unsupported/false as stated. It has no committed license text and performs user-triggered API fetches, not continuous real-time collection.
12. **“PumpTracker reports complete top traders/whales for 24 hours.”** False. It heuristically aggregates at most 50 recent enhanced transactions and applies no 24-hour filter.
13. **“PumpTracker needs no credentials and is fully free.”** False for the whole app. It exposes an owner Helius key in browser code; that credential is neither safe nor a reusable entitlement.
14. **“The live PumpTracker demo has an SLA.”** Unsupported. Two root pages returned HTTP 200 in one audit probe; no app/feature SLA is published.
15. **“`rckprtr/pumpdotfun-sdk` is the official/current Pump.fun SDK.”** False. It is third-party, its default branch is old, and its buy/sell IDL account/argument layouts differ materially from Pump's current official IDL.
16. **“Following the pumpdotfun-sdk README currently enables create-and-buy/buy/sell.”** Outdated. Any positive-buy or sell path uses stale instruction layouts and lacks the official v2 interfaces; the repository has no current protocol integration test.
17. **“`npm i pumpdotfun-sdk` installs audited GitHub main 1.5.2 under the same metadata.”** False at audit time. npm `latest` was 1.4.2/ISC while GitHub main declared 1.5.2/MIT.
18. **The pumpdotfun-sdk README's metadata/event examples match current source paths and types.** False: the README uses `filePath`, while source requires `file: Blob`, and names `example/events/events.ts` although the repository file is [`example/events/index.ts`](https://github.com/rckprtr/pumpdotfun-sdk/blob/3507b88e7c6371ec42cc111226b6e07bc599b867/example/events/index.ts).
19. **“pumpdotfun-sdk provides storage/replay.”** False. It creates transactions, reads accounts, and subscribes to live events only.
20. **“pumpdotfun-sdk is fully tested and free-only.”** Misleading. Tests are packaging smoke tests; write operations require a funded signer and on-chain fees.

## Availability/SLA rule for downstream claims

Use four separate labels:

1. **Source available:** repository could be fetched at audit time.
2. **Service observed:** a specific endpoint returned a valid response in a timestamped low-volume probe.
3. **Documented entitlement:** the owner promises access under stated plan/limits.
4. **SLA:** the owner contractually states uptime/support/remedy terms.

Do not promote (1) or (2) into (3), and never promote any of them into (4). None of these repositories, by itself, supplies a managed free SLA.
