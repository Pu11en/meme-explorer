# GoPlus Security API — adversarial candidate verification

**Checked:** 2026-08-26  
**Corrected status: REJECT under the stated hard constraints.** A live, documented, anonymous Solana lane exists, but the current owner pricing table meters even the Free Version in API CUs, explicitly provides no free-tier SLA, and GoPlus does not provide an identifiable legal license for returned API data. Each is disqualifying even though the no-key probe succeeded.

## Safe public no-key probes

No private key, signature, transaction, wallet, account, trial, payment, or undocumented endpoint was used.

1. `GET /api/v1/solana/token_security?contract_addresses=So11111111111111111111111111111111111111112` returned HTTP `200`, JSON `code: 1`, `message: "ok"`, and a populated result keyed by the Wrapped SOL mint.
2. Omitting the required address from that documented endpoint still returned HTTP `200`, but the JSON and `x-code` header reported application code `2007` with `message: "Not contract address!"`.
3. The same endpoint with Wrapped SOL plus the public USDC mint returned HTTP `200` but only the Wrapped SOL result, matching the SDK's documented anonymous first-token restriction.
4. `GET /api/v1/supported_chains` (the [documented endpoint](https://docs.gopluslabs.io/reference/getchainslistusingget)) returned HTTP `200` and included `{ "name": "Solana", "id": "solana" }`.
5. Probe responses exposed no `RateLimit`, `X-RateLimit-*`, or reset headers. No attempt was made to exhaust either published ceiling.

## Decision

**Reject**, not pass/conditional, for this strict candidate set. The technical anonymous lane currently works without presenting an account or balance, but GoPlus does not document it as durably exempt from the current CU-limited Free Version, and the older 30-calls/minute policy conflicts with the current CU pricing table. Independently dispositive failures are the missing legal returned-data grant and the lack of free-lane reliability support. Reconsider only if GoPlus publishes (1) binding API/data-use terms expressly granting the required storage/redistribution/commercial rights, (2) one unambiguous no-account/no-CU anonymous quota policy, and (3) an acceptable production SLA/status and freshness commitment for the Solana endpoint. The account/CU lane should remain excluded.
