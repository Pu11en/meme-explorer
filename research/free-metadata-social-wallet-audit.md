# Free metadata, social/domain, funding-history, and wallet-label paths — independent audit

**Audited:** 2026-08-26 UTC  
**Rule:** “Free-only” excludes a funded/provider wallet, paid or metered balance, payment card, paid package, and temporary trial. Key/account requirements are flagged separately. Owner documentation and bounded anonymous probes only. A successful request is **observed availability**, not an SLA, retention promise, or completeness guarantee.

## Executive verdict

| Area | Strict free-only prototype path | Access requirement | Reliability boundary |
|---|---|---|---|
| Token metadata/media | Read on-chain metadata through a public RPC, then fetch `https`, `ipfs`, or Arweave content directly | No key on Solana-operated RPC/public gateways; some hosted gateways require an account/key | Best-effort only; metadata is optional/self-asserted and gateways publish no relevant end-to-end SLA |
| Social/domain context | Metadata links plus ENS resolution, GitHub public resources, and registry RDAP | ENS reads depend on an RPC; GitHub/RDAP public reads need no key | Identity is not verified; GitHub/IP rate limits, RDAP redaction/operator policy, ENS normalization/forward checks and CCIP-Read failures apply |
| Wallet funding/history | Locally retain chain events; use bounded public-RPC history or keyless Blockscout indexing opportunistically | Solana/dRPC public RPC and Blockscout are no-key; Etherscan history requires a free API key | Public RPC/indexer history is not archive/completeness-guaranteed; EVM standard JSON-RPC has no general address-history index |
| Wallet labels | Locally curated, evidence-linked labels; optional sparse Blockscout/community hints | Etherscan metadata/label exports are paid PRO endpoints; ENS is not a label feed | No broad, authoritative, no-key, SLA-backed wallet-label service was found |

No reviewed path is an SLA-backed “free production dependency.” The viable result is a **best-effort production prototype** with local retention, explicit missingness, provenance, retries, and source-specific circuit breakers.

## 1. Token metadata and media

- **Solana:** Metaplex metadata gives on-chain name/symbol/URI, creators, update authority, and mutability; URI JSON/media/socials remain issuer-controlled off-chain claims. Read the account through RPC, retain raw bytes/slot/commitment, and separately record fetch status, redirect chain, MIME, byte limit, content hash, and timestamp. Token-2022 metadata/extensions require separate decoding. Sources: [Metaplex Token Metadata](https://www.metaplex.com/docs/smart-contracts/token-metadata), [Solana token extensions](https://solana.com/docs/tokens/extensions), [Solana public endpoints](https://solana.com/docs/references/clusters).
- **EVM:** ERC-721’s metadata extension is optional; missing/reverting/malformed `tokenURI` is valid input, not necessarily an RPC failure. ERC-1155 defines URI substitution rules but still depends on the returned host. PublicNode advertises a directly usable no-key Ethereum endpoint for `eth_call`, but publishes no consumer SLA or stable rate-limit entitlement on the reviewed owner page. Sources: [ERC-721](https://eips.ethereum.org/EIPS/eip-721), [ERC-1155](https://eips.ethereum.org/EIPS/eip-1155), [Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/), [PublicNode](https://publicnode.com/).
- **Arweave reads:** owner docs show direct gateway GETs such as `https://arweave.net/<TXID>` without a read key/account/card/balance. A bounded `https://arweave.net/info` request returned HTTP 200 on the audit date. That proves current gateway reachability only. AR.IO explicitly warns that `arweave.net` is one access point and should not be assumed available forever; network permanence/data availability is not a consumer SLA for one HTTP gateway. Use gateway fallback and caching. Sources: [Arweave HTTP API](https://docs.arweave.org/developers/arweave-node-server/http-api), [AR.IO fetch data](https://docs.ar.io/build/access/fetch-data), [AR.IO gateway warning](https://ar.io/articles/arweave-dot-net/), [gateway architecture](https://docs.ar.io/learn/gateways/).
- **Arweave uploads do not qualify:** Turbo uploads use credits/payment and wallet signing. Existing public data can be read free-only; publishing new metadata/media requires a paid balance/payment method. Sources: [bundling services](https://docs.ar.io/build/upload/bundling-services), [Turbo credits](https://docs.ar.io/build/upload/turbo-credits).
- **IPFS fallback:** IPFS calls public gateways a shared, best-effort public good with no SLA/support and shared throttling. Cloudflare Web3 Gateways has a free plan but requires a Cloudflare account/site setup. Sources: [IPFS public-gateway warning](https://docs.ipfs.tech/how-to/replace-public-gateways-with-self-hosted-ipfs/), [Cloudflare setup](https://developers.cloudflare.com/web3/get-started/), [Cloudflare limits](https://developers.cloudflare.com/web3/reference/limits/).

## 2. Social and domain context

- Treat website/X/Telegram/GitHub fields as **self-asserted strings**, not ownership or reputation. Resolve redirects safely and never equate presence, age, follower count, or a matching display name with common control.
- **ENS reads:** normalize with ENSIP-15 before hashing/resolution. A reverse/primary name is valid only when the name forward-resolves to the same address. Text records are arbitrary UTF-8, names expire/change, wildcard names may not be enumerable, and Universal Resolver calls may invoke CCIP-Read/off-chain gateways. ENS therefore supplies a user-controlled alias, not a verified wallet label or identity. Reading can be free-only via a no-key RPC; registering/renewing `.eth` costs registration fees plus gas and fails the strict rule. Sources: [name processing](https://docs.ens.domains/resolution/names/), [ENSIP-15](https://docs.ens.domains/ensip/15/), [primary-name warning](https://docs.ens.domains/web/reverse/), [CCIP-Read](https://docs.ens.domains/resolvers/ccip-read/), [`.eth` pricing](https://docs.ens.domains/registry/eth/).
- **GitHub:** public REST resources can be read without authentication, but unauthenticated traffic is limited to 60 requests/hour per originating IP and can also hit secondary limits. The audit’s anonymous `GET /repos/octocat/Hello-World` returned HTTP 403 because the shared IP quota was already exhausted—direct evidence that “no key” is not dependable availability. Cache by commit SHA/ETag; do not scrape UI pages. Sources: [public repository contents](https://docs.github.com/en/rest/repos/contents), [rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api), [troubleshooting limits](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api), [GitHub Terms](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service).
- **RDAP:** fetch IANA’s DNS bootstrap, select the registry operator’s base URL, then query `/domain/<domain>`. Bounded no-key requests to IANA’s bootstrap and Verisign’s `example.com` RDAP endpoint returned HTTP 200. This is genuinely useful anonymous context—registrar, dates, statuses, nameservers, DNSSEC—but responses may redact ownership data and each operator may impose redirects, authorization, and rate limits. It does not prove who controls the linked site. Sources: [IANA RDAP bootstrap](https://www.iana.org/assignments/rdap-dns), [RFC 9082](https://www.rfc-editor.org/rfc/rfc9082.html), [ICANN RDAP information](https://www.icann.org/en/contracted-parties/registry-operators/registration-data-access-protocol/information-for-rdap-users-31-08-2018-en), [RFC 9537 redaction](https://www.rfc-editor.org/rfc/rfc9537.html).

## 3. Wallet funding and transaction history

- **Solana public RPC:** `getSignaturesForAddress` returns at most 1,000 signatures per call and requires `before` pagination; `getTransaction` can still return `null`. Solana says its public endpoints are not intended for production, limits may change without notice, and high-traffic clients may be blocked. `getFirstAvailableBlock`/`minimumLedgerSlot` do not prove complete address history. “Wallet age” must mean **earliest retrievable activity from named sources**, never account-creation time. Sources: [`getSignaturesForAddress`](https://solana.com/docs/rpc/http/getsignaturesforaddress), [`getTransaction`](https://solana.com/docs/rpc/http/gettransaction), [public-endpoint warning](https://solana.com/docs/references/clusters).
- **EVM standard RPC:** the standard exposes blocks/transactions/receipts and contract logs, but no general “all transactions touching this address” method. `eth_getLogs` covers emitted logs, not every external call, internal value transfer, or native funding path. Complete funding provenance therefore needs a locally retained index/full scan with traces, or an indexed explorer/provider. Source: [Ethereum JSON-RPC method set](https://ethereum.org/developers/docs/apis/json-rpc/).
- **dRPC public Ethereum RPC:** owner docs say public nodes are always free but rate-limited, with no account/key/card/trial/balance for `https://eth.drpc.org`. Bounded probes observed historical state and filtered log queries, while an unfiltered 10,000-block log query timed out with an upgrade message. This is useful best-effort historical RPC, not an address index or documented public-node SLA. Source: [dRPC rate limiting](https://drpc.org/docs/howitworks/ratelimiting).
- **Blockscout keyless indexing:** owner docs publish a shared pool of 5 requests/second with no registration required. A bounded ascending address-history request returned HTTP 200 and an earliest inbound transaction, so normal/internal/token-transfer endpoints can derive a first **observed indexed** funder. Query categories separately, paginate, and never call it canonical or complete; no shared-pool SLA was found. Sources: [address transactions](https://docs.blockscout.com/api-reference/account/get-a-list-of-transactions-by-address), [requests and limits](https://docs.blockscout.com/devs/apis/requests-and-limits).
- **Etherscan normal address history:** `txlist` is available on the Free tier but **requires an Etherscan API key**. Current owner limits are 3 calls/second and 100,000/day for Free; PRO endpoints are unavailable. A bounded no-key request returned HTTP 200 with `NOTOK` / `Missing/Invalid API Key`. Thus it is zero-price keyed access, not no-key access and not an SLA. Sources: [`txlist`](https://docs.etherscan.io/api-reference/endpoint/txlist), [rate limits](https://docs.etherscan.io/rate-limits), [API-key help](https://etherscan.io/help/etherscan/developer/i-need-an-api-key).
- **Etherscan “Address Funded By”: exclude.** Owner docs mark it PRO, Standard plan and above, at 2 calls/second; it covers the first funder of an EOA and is not available for contracts. It requires a paid plan plus API key and is not complete multi-hop provenance. Source: [Get Address Funded By](https://docs.etherscan.io/api-reference/endpoint/fundedby).

## 4. Wallet labels

- **Etherscan labels are not free-only:** the current endpoint-specific page marks “Get Metadata for an Address” exclusively Pro Plus and caps it at 2 calls/second; this overrides any ambiguous/stale Free-plan marketing. Bulk/export address tags are Enterprise (legacy export: 2 calls/second and 100/day). Both require an API key and paid plan. Sources: [address metadata](https://docs.etherscan.io/api-reference/endpoint/getaddresstag), [address-tag export](https://docs.etherscan.io/api-reference/endpoint/exportaddresstags), [rate limits](https://docs.etherscan.io/rate-limits).
- **Blockscout is sparse context, not a label corpus:** keyless address responses can include `ens_domain_name` and `public_tags`, but a bounded test returned empty public tags for a well-known address. Coverage and provenance are instance/indexer dependent and no shared-pool SLA was found. Source: [address info](https://docs.blockscout.com/api-reference/get-address-info).
- **ENS is not a substitute:** it is owner-set naming and must pass normalization plus reverse/forward verification; it does not establish exchange, scammer, deployer, or common-controller status.
- **Community/static labels:** `eth-labels` publishes a public repository and advertises a free API, but no rate/SLA or sufficiently broad provenance guarantee was found. If licensing/provenance review passes, pin a commit and treat every row as a revocable community assertion—not owner truth. Source: [`dawsbot/eth-labels`](https://github.com/dawsbot/eth-labels).
- **WalletLabels:** owner docs require an API key even though they claim no current rate limits; the API hostname failed DNS resolution in a bounded probe. Exclude it from the free no-key baseline and from any availability claim. Source: [WalletLabels API reference](https://docs.walletlabels.xyz/content/api-references).
- **RugCheck is no longer a current contract:** prior repository probes observed anonymous `knownAccounts`/insider-like fields, but the cited owner Swagger JSON returned HTTP 404 during this audit. Until owner documentation returns, exclude it as a dependency rather than promoting previously observed fields. Prior detail: [`free-holders-creator-risk-enrichment-audit-2026-08-26.md`](free-holders-creator-risk-enrichment-audit-2026-08-26.md).
- The defensible free-only implementation is a local append-only label table with `address`, `chain`, narrow label, evidence URL/hash, source owner, first/last observed timestamps, confidence/status, and revocation history. Never infer actor identity from co-funding or one transfer alone.

## 5. Etherscan date correction

Etherscan’s owner changelog says **updated May 1, 2026; effective July 1, 2026** for the Free-tier per-request reduction from 10,000 to 1,000 records on named historical endpoints. The current `txlist` page was modified after that effective date during this 2026-08-26 audit. Therefore:

- a draft written **before 2026-07-01** must describe 1,000 as an announced future limit, not current behavior;
- an audit on/after the effective date may use 1,000, but should cite the effective date and still contract-test pagination;
- the dated notice does **not** make Etherscan no-key, SLA-backed, or suitable for free labels/funder lookup.

Source: [Etherscan changelog](https://docs.etherscan.io/changelog). Avoid copying future-dated search snippets without recording the page’s effective/access date.

## 6. Prototype recommendation and repository cross-check

1. Store launch/chain events locally first; enrich asynchronously and preserve raw response, source, time, slot/block, commitment, and explicit `missing` versus `fetch_failed` states.
2. Fetch metadata/media through a sandboxed allowlisted client with DNS/IP SSRF defense, redirect/size/time limits, MIME sniffing, hashing, and multiple content-addressed gateways.
3. Use ENS/GitHub/RDAP only as context. Record validation/redaction/rate-limit state and never promote them to identity claims.
4. Compute funding facts from retained raw events where possible; use dRPC/Blockscout as independent best-effort backfill. Name the observed coverage window and do not claim “first-ever funder” from incomplete RPC/indexer history.
5. Keep wallet labels local and evidence-linked; third-party labels remain timestamped assertions.

The repository contains planning and research Markdown only—no implementation, package/config, or environment files to wire, and no prior Etherscan/ENS/GitHub/RDAP draft was found. Existing boundaries in [`planning/PLAN.md`](../planning/PLAN.md) correctly exclude paid APIs, funded-provider wallets, and metered data. Existing public-RPC and holder audits correctly distinguish protocol capability/observed responses from production guarantees. The main additions from this audit are the Etherscan keyed/paid split, the absence of a broad free wallet-label path, direct Arweave-read versus paid-upload distinction, ENS forward-verification/normalization warnings, and GitHub/RDAP anonymous-access limits.
