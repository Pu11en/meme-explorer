# Candidate Pump.fun / Solana variables — primary-source draft

**Scope.** Candidate variables observable at or soon after a new Pump coin is created. Sources are restricted to the official `pump-fun/pump-public-docs` repository (including Pump and PumpSwap IDLs), official Solana RPC specifications, and PumpPortal's own provider documentation. PumpPortal describes itself as a **third-party** API, so its feed is treated as a direct provider claim, not as protocol truth.

**Important evidence boundary.** The primary sources below establish field semantics, events, and access methods. They do **not** establish that any variable predicts whether a token will be “promising” or “poor.” Every item is therefore a research candidate, not a validated signal. Predictive value requires a separately specified label, point-in-time backtest, and out-of-sample evaluation.

**Official Pump snapshot used.** Public docs commit [`9c82f61cb711b044a17f770ab8ce9f9bdf78f333`](https://github.com/pump-fun/pump-public-docs/tree/9c82f61cb711b044a17f770ab8ce9f9bdf78f333).

## Evidence-status legend

- **Direct / protocol:** explicitly represented by an official Pump account, instruction, or emitted event.
- **Derived / chain:** deterministic calculation from protocol fields and official Solana RPC responses; the exact derived metric is not defined by Pump.
- **Provider claim:** PumpPortal says its feed exposes the event; verify against finalized chain data.
- **Heuristic only:** a proposed attribution or coordination proxy. It is observable/derivable, but no cited primary source validates it as bot, sybil, or quality evidence.

|---|---|---|---|---|

## Suggested point-in-time dataset contract

This is a measurement contract, **not a claim about usefulness**:

1. **Unit:** one Pump mint.
2. **Anchor:** finalized `CreateEvent` signature, slot, block time, creator, creation user, curve PDA, quote mint, and program/IDL version.
3. **Feature cutoffs:** fixed horizons (for example 0s, 5s, 30s, 120s, 10m) with `observed_through_slot` and `commitment` stored for every snapshot.
4. **Reconciliation:** low-latency processed stream may trigger collection, but canonical rows are reconciled against confirmed/finalized Solana transactions and accounts.
5. **Missingness:** distinguish no event, RPC unavailable, provider disconnect, history unavailable, and right-censored outcome.
6. **Inventory exclusions:** publish raw and adjusted concentration; list excluded curve/pool vault addresses explicitly.
7. **Identity discipline:** address ≠ person. Keep protocol `creator`, transaction `user`, token-account owner, fee beneficiary, and inferred cluster as separate fields.
8. **Outcome discipline:** define “promising/poor” independently (horizon, return/liquidity/survival criteria, base currency, censoring). Do not construct features with data after their decision cutoff.

## Bottom line

The strongest **measurement provenance** comes from finalized Pump/PumpSwap events and accounts, with Solana RPC used to reconstruct transactions, token balances, and address histories. PumpPortal is useful as a low-latency trigger but explicitly reports processed commitment and third-party delivery limitations. Creator-history, concentration, curve progress, early order flow, migration, and liquidity variables are all measurable candidates. Bot/sybil variables remain attribution heuristics. None of the allowed primary sources supplies evidence that these variables distinguish future winners from losers.
